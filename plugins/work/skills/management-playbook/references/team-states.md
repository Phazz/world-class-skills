# An Elegant Puzzle: manage the system

Apply a selective synthesis of Will Larson's *An Elegant Puzzle: Systems of Engineering Management* (2019), grounded in his public essays. Treat the organization as a system whose accumulated state and feedback explain recurring behavior.

## Diagnose before intervening

Classify each relevant team using evidence rather than morale labels:

| State | Observable condition | Intervention to consider |
| --- | --- | --- |
| Falling behind | Incoming work exceeds completion; backlog keeps growing | Add effective capacity, with realistic onboarding delay |
| Treading water | Essential work gets done, but improvements do not | Reduce recurring work so capacity becomes available |
| Repaying debt | Capacity exists to improve inherited systems | Pay down constraints that keep recreating work |
| Innovating | The team can sustainably pursue new value | Preserve slack and avoid disruption that destroys capacity |

These are diagnostic categories, not performance grades. Validate the state across time. A hiring recommendation requires evidence that staffing is the actual constraint; where hiring is unavailable, explicitly consider reducing commitments.

## Model the mechanism

Identify accumulated quantities such as backlog, technical debt, trained engineers, and trust. Identify rates that change them, including demand, delivery, onboarding, and attrition. Include feedback and delay: incidents consume improvement time, neglected improvements generate more incidents, and onboarding initially consumes experienced attention.

Find the limiting flow before optimizing another one. Use a rough causal sketch first; add numbers only when they improve the decision. A model is a hypothesis to compare with observed behavior.

## Turn diagnosis into action

The following operating procedure is an adaptation for this skill:

1. Gather workload trends, interruption sources, ownership gaps, and available capacity. Avoid using utilization alone as proof of effectiveness.
2. Compare a few interventions by capacity created, transition cost, time to benefit, and effect on neighboring teams.
3. Prefer a targeted intervention with an explicit causal explanation. Do not prescribe a reorganization merely to signal action.
4. Name the accountable owner, what will stop or wait, and the first observation that should change if the diagnosis is right.
5. Set a review horizon that accounts for delays. Distinguish a slow expected recovery from evidence the diagnosis was wrong.

For organizational design, ask whether a team can own a coherent outcome with its actual staffing and dependencies. Treat numerical staffing heuristics as context-sensitive starting points.

## Deliverable

Return team-state evidence, a causal explanation, the chosen intervention and rejected alternative, transition costs, and review signals. For example, a growing support queue should trigger a demand-versus-capacity investigation before a new delivery ritual.

## Completion check

The diagnosis is ready when team-state claims have trend evidence or are marked provisional, the intervention names the flow it changes, and the review signal accounts for transition delay. Include the capacity or commitment that pays for the intervention.
